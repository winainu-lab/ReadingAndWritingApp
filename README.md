# อ่านคล่อง นม.2

เว็บแอปประเมินการอ่านสำหรับศึกษานิเทศก์และครูผู้ทดสอบในสังกัด สพป.นครราชสีมา เขต 2 พัฒนาด้วย React, TypeScript, Vite และ Supabase

## ความสามารถใน MVP

- สมัครครูผู้ทดสอบและรอผู้ดูแลอนุมัติ
- บทบาทผู้ดูแลระบบ ศึกษานิเทศก์ และครูผู้ทดสอบ
- โรงเรียน 175 แห่ง แยก 17 ศูนย์เครือข่าย และ 5 อำเภอ
- เพิ่ม แก้ไข และปิดใช้งานโรงเรียนแบบไม่ทำลายประวัติเดิม
- เรียงและแบ่งกลุ่มโรงเรียนตามศูนย์เครือข่ายทั้งหน้ารายการและช่องเลือก
- สร้างห้องจากระดับชั้น ห้อง ปีการศึกษา และจำนวนนักเรียน
- ผู้สร้างห้องหรือผู้ดูแลนำห้องออกจากงานปัจจุบันได้ โดยไม่ทำลายผลประเมินย้อนหลัง
- สร้างนักเรียนสมมติ `นักเรียนคนที่ 1, 2, 3…` โดยไม่เก็บข้อมูลส่วนบุคคล
- คลังทักษะ 24 บท พร้อมหน้าตรวจคำ เพิ่มคำ และแก้ไขคำอ่าน
- เพิ่ม แก้ไข เปิด/ปิด และลบแบบเก็บประวัติสำหรับแบบทดสอบ
- แอดมินสร้างบัญชีที่อนุมัติแล้วได้ทันที และอนุมัติ/ระงับผู้สมัครพร้อมกำหนดโรงเรียน
- หน้าทดสอบพร้อมจับเวลาและบันทึก อ่านถูก อ่านผิด แก้ไขเอง หรือข้าม
- แดชบอร์ดและรายงานแยกศูนย์เครือข่าย พร้อมส่งออก CSV
- ผู้ดูแลเปลี่ยนชื่อระบบ ชื่อสังกัด ข้อความต้อนรับ และข้อความท้ายเว็บไซต์ได้
- หน้าแรกแบบงานนำเสนอสัดส่วน 16:9 พร้อม modal เข้าสู่ระบบ/สมัครสมาชิก
- คลัง “ศึกษาเอกสารและใบความรู้” แบบสาธารณะ ค้นหา/กรองได้ พร้อมการ์ดสัดส่วน A4 และภาพหน้าแรกจาก Google Drive
- ผู้ดูแลเพิ่ม แก้ไข ลบ ซ่อน และล็อกเอกสาร รวมทั้งกำหนดภาพปกเองได้
- ผู้ดูแลอัปโหลดโลโก้ PNG, JPG, WEBP หรือ SVG ไปยัง Supabase Storage ได้ (ไม่เกิน 2 MB)
- ธีมสีเหลืองทองพร้อมลายกนกขนาดเล็ก แอนิเมชันเปลี่ยนหน้า และรองรับมือถือ แท็บเล็ต และคอมพิวเตอร์
- Row Level Security จำกัดครูให้เข้าถึงห้องและนักเรียนในโรงเรียนของตน

## เริ่มระบบในเครื่อง

ต้องเปิด Docker Desktop ก่อน จากนั้นรัน:

```bash
npm install
supabase start
supabase migration up
npm run functions:serve
npm run dev
```

เปิด `http://localhost:5173`

สร้าง `.env.local` จาก `.env.example` แล้วใช้ Project URL และ Publishable key ที่ได้จาก `supabase status` ห้ามนำ Secret key หรือ Service Role key ไปใส่ใน Vite

Migration จะสร้าง Storage bucket ชื่อ `branding` สำหรับโลโก้โดยอัตโนมัติ ผู้ใช้ทั่วไปอ่านโลโก้ได้ แต่มีเพียงผู้ดูแลระบบที่อัปโหลด แก้ไข หรือลบไฟล์ได้

เอกสารใน Google Drive ต้องตั้งเป็น “ทุกคนที่มีลิงก์ดูได้” เพื่อสร้างภาพตัวอย่างอัตโนมัติ สถานะล็อกจะซ่อนปุ่มและ URL จาก API สาธารณะของแอป แต่ไม่ใช่การเพิกถอนสิทธิ์ของไฟล์ต้นฉบับใน Google Drive

ระหว่างพัฒนาให้เปิด `npm run functions:serve` และ `npm run dev` คนละหน้าต่าง คำสั่งแรกให้บริการฟังก์ชันฝั่งเซิร์ฟเวอร์สำหรับแอดมินสร้างบัญชี โดย Service Role key จะอยู่เฉพาะใน Supabase runtime และไม่ถูกส่งเข้าเบราว์เซอร์

## บัญชีตัวอย่างสำหรับ local เท่านั้น

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลระบบ | `admin@korat2.local` | `Admin1234!` |
| ศึกษานิเทศก์ | `supervisor@korat2.local` | `Supervisor1234!` |
| ครูผู้ทดสอบ | `teacher@korat2.local` | `Teacher1234!` |

บัญชีเหล่านี้อยู่ใน `supabase/seed.sql` และ `supabase/demo_seed.sql` เพื่อการพัฒนาเท่านั้น ต้องไม่ใช้บน production

## ตรวจสอบก่อนส่งขึ้นระบบ

```bash
npm run build
supabase db reset
npm run db:types
```

## นำขึ้น Supabase และ Vercel

1. สร้าง Supabase project สำหรับ production
2. ใช้ `supabase link --project-ref <project-ref>`
3. ตรวจ migration ด้วย `supabase db push --dry-run`
4. ใช้ `supabase db push` โดยไม่ส่ง demo seed ขึ้น production
5. ใช้ `supabase functions deploy admin-create-user` เพื่อนำฟังก์ชันสร้างผู้ใช้ขึ้น Supabase
6. ตั้ง `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` ใน Vercel
7. เชื่อม Git repository กับ Vercel และ deploy

`vercel.json` มี SPA rewrite สำหรับเปิด URL ย่อยโดยตรงแล้ว
